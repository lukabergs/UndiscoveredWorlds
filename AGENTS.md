# Undiscovered Worlds

Procedural planetary simulation (terrain, tectonics, climate, hydrology, early society) in C++17/CMake/vcpkg on Windows. `README.md` describes the intended lifecycle; distinguish intended from implemented behaviour. Design and status live in `docs/architecture/` (`master-plan.md`: the running plan, every open item in numbered phases; `world-model.md`: components, process kinds, recipes; `sphere-mesh.md`: the cube world grid). `meta/`, `refs/` and `runs/` (except `runs/registry/` and `runs/ledger/`) are local-only and gitignored.

## Working conventions

- **Tracks and triage (the user, 2026-10-21).** Broad goals run one track at a time, streamlined like T8 (the cube): parallel workers within the track, not across tracks; the order is in the running plan's §1 "Tracks". An issue seen during a task is first triaged: if it belongs to the task in progress, it is fixed in that task; if it belongs to later work, it goes as one row into the phase that owns it and the current work continues. No chain of new steps spun off from steps.
- **No prompt while questions are open (the user, 2026-10-21).** The next session's prompt is printed only when every question to the user is answered; until then the session asks all of them in one message.
- The prompt for the next session is printed in the chat, never saved in the plan or another document (user, 2026-10-08). The exception of 2026-10-10 (`multiscale-plan.md` keeping its own handoff in §7 "Next") ended on 2026-10-13. **The running plan is `docs/architecture/master-plan.md`** (since 2026-10-20: numbered phases 1 to 17, steps `phase.step`, lanes for parallel waves); every other plan (`terrain-roadmap.md`, the multiscale, erosion and consolidation plans, `docs/tasks/`) is a record.
- Before ending a phase or printing the prompt for the next one, write what the session learned where the next agent will read it (this file, the plan, the ledger, the guides, memory): nothing stays only in the conversation.
- Work directly on `main`; uncommitted changes in the working tree are current work, so build on them and never reset, stash or revert them.
- **Autonomy (the user, 2026-10-18): agents never ask the user for permission.** They run scripts, builds, runs, the tests a brief names, commits and pushes, and delete what git can restore (tracked files without uncommitted changes). Deletes git cannot restore are refused by the PreToolUse hook `scripts/uwtools/delete_guard.py`, not by judgment: untracked or ignored files and folders (`refs/`, `runs/`, `out/scratch`, D:), uncommitted changes (`git clean`, `reset --hard` or `restore` on a dirty tree), `stash drop`, `branch -D`, `worktree remove`, `storage.py finish --accept-newer`, `worktrees.py retire --allow-unlanded`, and any deleter fed by a pipeline. **Since 2026-10-20 (the user) agents also clean up on their own through code that verifies before it removes:** untracked data they no longer need goes to the trash with `scripts/uwtools/trash.py move PATH --reason TEXT` (a move to `D:/dev/undiscovered-worlds/trash/` with a receipt, `list`, `restore ENTRY`; only the user empties it); merged worktrees are retired with `worktrees.py preserve` then `retire --yes` (refuses unless every added line is in main); their branches go with `worktrees.py drop-branches --retired` (bundles, verifies and checks heads first); a leftover migration backup goes with `storage.py finish PATH`. A second hook, `scripts/uwtools/guard_catastrophe.py` (global, every project), refuses disk and volume tools, refuses any command holding a delete word unless it is one recognised deleter with literal paths (no pipeline, variables, loops, inline code or command substitution), and refuses deleting, moving or mirroring a drive root or a path within two levels of one, system folders, the home folder and its children, `.git`, `refs/`, `D:/dev/bak`, the storage root's `worktree-archive`, `receipts` and `trash`, and the `out`, `runs`, `src`, `scripts` folders whole. Both guards run through `scripts/uwtools/hook_runner.py`, which turns any failure of a guard into a block. So delete with one literal command per path (`rm -rf C:/dev/undiscovered-worlds/out/build/x`), never in a loop or a pipeline, and write a commit message that mentions deletes to a scratchpad file and commit with `git commit -F FILE` (both guards read `-m` text as commands). Underneath both guards, since 2026-10-20 (the user), `scripts/uwtools/protect.py` puts an NTFS deny-delete permission (Everyone denied DELETE and DELETE_CHILD, inherited) on `refs/`, its storage side `D:/dev/undiscovered-worlds/refs`, `D:/dev/bak`, `worktree-archive` and the trash: nothing inside can be deleted, renamed or moved away by any process, while creating and overwriting in place still work. Code writing there must copy or overwrite in place, never replace by rename or delete temp files (atomic writes fail); `protect.py status` shows the state, and only the user unlocks (`unlock` and `harden` are refused for agents, as are icacls, takeown and Set-Acl). **Never test either guard by attempting a delete or by feeding it delete commands (the user, 2026-10-20): change a guard by reading it, and have a reviewer read the change.** When a guard blocks, do not retry or work around it: use the trash if it applies, else add the path and the reason to the "For the user" list in the running plan and continue. A decision that would otherwise go to the user (an API, format or contract change, a calibration round) is taken with the recommended option and recorded with its reason in the plan. This overrides the global "ask before" rules, except that new production dependencies stay out.
- Never link `refs/` (or any data directory) into a git worktree, and never remove a worktree that may hold a link: a recursive delete follows junctions (2026-10-07, most of `refs/processed` lost). Agent worktrees are retired only by `scripts/uwtools/worktrees.py`: `preserve` (the uncommitted patch and every untracked file except `.venv/` and `out/build/`, SHA-256-verified, to `D:/dev/undiscovered-worlds/worktree-archive/<name>/`), then `retire --yes` (refuses on any link, a moved HEAD or a changed diff; deletes without following links; keeps the branch); never git's forced worktree removal; `retire` is routine for agents since 2026-10-20 (the user) and refuses a worktree whose work is not all in main. A retired worktree's branch is deleted only by `worktrees.py drop-branches` (a bundle in `D:/dev/undiscovered-worlds/worktree-archive/branches-<stamp>.bundle`, `git bundle verify`, every head matched, a receipt, then `git branch -D`). A worker in a worktree writes runs and scratch to the main tree's `out/scratch` by absolute path (on D). Workers read `refs/` by absolute path; `D:/dev/bak` holds the copy of `refs/` and the other untracked data (`scripts/uwtools/backup.py`).
- Every step records its wall-clock duration (user, 2026-10-06), measured from the previous step's commit to the step's own commit (`git log --format='%h %ci'`; the first step of a phase counts from the phase's parent commit). A step's ledger entry has `phase` (`master plan <id>: ...`), `duration` (`start <hash> (<time>); ...` with the worker's minutes; its own commit-to-commit figure is only known at its commit) and `not_run` (a list); the plan's §4 status row has Commit `this commit`, replaced with the hash by the next step, and Duration `<who> N min; N min from <hash>`; `scripts/check_records.py` checks both, in the pre-commit hook and `step_check.py` (`docs/reference-guides/agent-workflow.md`, "Status row and ledger entry"). Durations are what the plan's estimates are checked against later.
- A compile build is the default check. Run tests, benchmarks, profile experiments, `check_tectonics_cli.py` or the Python suite only when asked or when a bug persists after a fix; say which checks were skipped. Commands are in `docs/reference-guides/verification.md`.
- The desktop application is compiled, never checked: the user works on the command line for now (2026-10-05), so a change in `src/app` is compile-only and says so in its ledger entry. Seed 1 for every new run; another seed only when the user asks for a seed comparison (20260906 only to reproduce climate runs up to 365). Module checks go through `scripts/uw.py <module> <command>` and the headless CLIs; never launch `UndiscoveredWorlds.exe` for a check.
- Tectonics has exactly one implementation, `src/simulations/geology/plate_tectonics` (namespace `tectonics::`, baseline from `configs/tectonics-baseline.json`). Do not reference or describe any other or former tectonics code. `scripts/check_layout.py` enforces its public-header boundary.
- Roles, models and checks are in `docs/reference-guides/agent-workflow.md`: the lead plans and reviews on Opus 5.5 (Fable 5.1 set aside by the user on 2026-10-17 for its token usage; every role that used it runs on Opus 5.5); a phase is run by an Opus 5.5 session that dispatches the project agents (`surveyor` for read-only surveys, `worker` and `mechanic` for bounded steps, `reviewer` for a fresh-context check of a finished step). Delegate read-only surveys to subagents and keep working. Before claiming a run improved anything, have a fresh-context reviewer check the evaluation (paused since 2026-10-05: the user says when reviews start again; `docs/architecture/consolidation-plan.md`, rules of Phase 4). Never write per-run HTML or scripts: reports are rendered from JSON by `scripts/evaluation/`.

## Where things go

- Behaviour in `src/simulations/<module>/`, stage order and recipes in `src/pipeline/`, I/O in `src/io/`, observed-data comparisons in `src/validation/`, GUI only in `src/app/` (its state and screens are `Application`, `src/app/application.hpp` and `src/app/screens/`; the legacy regional generator is `src/simulations/regional/` (`uw_regional`), called by the desktop only; the seamless regional pass of erosion plan Phase E is planet-free in `src/simulations/landscape/`). One translation unit per process, named by its process id. `src/world/functions.hpp` is a compatibility umbrella; include the owning header instead. Project headers are included by their path from `src/` (`#include "pipeline/world_processes.hpp"`); each directory is one static library `uw_<dir>` with its own `CMakeLists.txt`. `scripts/check_layout.py` enforces the include root and the layering: `core` includes only `core`; `simulations` and `pipeline` never include `app` or `cli`; SFML and ImGui only in `app`.
- Continuous world quantities are float: elevation and the six components added to it, lake surfaces, temperature, rain. Code in `src/simulations` and `src/pipeline` reads the `...float` getters (`nomfloat`, `mapfloat`, `mountainheightfloat`, `lakesurfacefloat`, `jantempfloat`, ...) and asks `basebelowsea(x, y)` or `surfacebelowsea(x, y)` instead of comparing an elevation with sea level. The getters without the suffix round to whole numbers and exist for the regional map, the GUI, the `.uww` layout and the three places that store whole values on purpose (the map imports in `src/io`, the import screen's element functions in `import_elements.cpp`, the drain paths in `world_stages.cpp`); do not add callers (what is left and why: plan §11, "Later"). `climateworld` has `basebelowsea(x, y)` too (since 2026-10-06). Codes, counts, masks, directions and 0 to 100 scores stay integers.
- Tunable values live in `configs/parameters/<module>.json` (keys in snake_case, read in code as `tuning::<module>::<group>::<camelCase>`). `scripts/parameters.py` generates the tracked `<module>_parameters.hpp` from it (`--check` in the step check); never edit a generated header or add a tuned constant to a source. A run sets a value with `--set <module>.<group>.<key>=value` or `--parameters FILE`, and the bundle manifest records all of them.
- Downloads and receipts in `refs/source/`, prepared inputs in `refs/processed/`, run artefacts in `runs/`, builds and scratch in `out/`. Bulk directories are junctions into `D:/dev/undiscovered-worlds/` (`runs/storage.json`): `runs/<module>/`, `runs/reports/<name>/`, and since 2026-10-17 `out/scratch/` and `out/evaluation/` whole (C filled up; `out/build` stays on C). Keep repo-relative paths, never replace a junction with a directory, and create run and report directories through `scripts/uwtools/storage.py` (`run_directory`, `route`). Never start a render or run while `route` is copying a tree it will replace. Space on C is watched automatically: the project hook (`.claude/settings.json`, SessionStart) prints `scripts/uwtools/storage.py status` (free space, a warning below 60 GB, leftover `*.storage-migration-backup` trees, agent worktrees); act on what it lists before starting runs. A swap whose clean-up stopped is finished with `storage.py check <path>`, then `storage.py finish <path>` (it deletes the old tree only when every file in it matches the receipt and the storage copy). `out/build` stays on C (build speed); everything bulky goes through the two junctions, so nothing has to be moved after a task. Registered runs live in `runs/<module>/<id>/` (`scripts/uwtools/runs.py` finds a run in either layout); `runs/archive/` is the sealed earlier layout and is never written. `scripts/repository_scope.py` enforces the 5 MiB blob limit and local-only paths. `scripts/check_structure.py` enforces the places named here from `configs/structure.json` (unnamed folders, file kinds a folder does not take, HTML outside `scripts/evaluation/templates`, `out/evaluation`, `runs/reports` and a run's `evaluation*` folder, scripts under `runs/`, any write to `runs/archive/`); it runs in `step_check.py` and as a PreToolUse hook on Write and Edit that judges new files inside the repository. A new place goes into the config (orchestrator), never around the hook.

## Simulation evidence

- Separate deterministic correctness from physical validity: an unchanged seed or a passing test does not show improved skill; compare the affected fields and metrics, and expect a visual review. Observed Earth data are validation inputs, never hidden forcing for procedural worlds; keep assumptions and calibrations explicit.
- A refactor that must not change results is checked with seed-1 `world_pipeline --bundle` runs compared by `scripts/evaluation/compare_bundles.py`, at the minimal configuration (`--resolution 128`, `--duration 50`, `--climate-resolution 32 --climate-coupling-iterations 2`: about two minutes for the procedural recipe and under one for the others; on the cube of N 32 by default since T8 W3.2, `--grid latlon` for 128 x 64 lat-lon parity); `scripts/evaluation/step_check.py <label> --reference <previous> [--grid latlon]` does the builds, the three runs, the comparison and the layout, parameter and access checks; larger runs are for judging a module, not for parity; a stage whose writes change keeps its declared access current (`--audit-access`, `scripts/evaluation/process_access.py`). Measure access (the tracking build and its report runs) only when a change alters which fields a process reads or writes, never as a routine check; a change of number type is not such a change. Build the desktop preset only when `src/app` changes.
- What the minimal world cannot show: it has no mountains, craters, ocean ridges or lakes (those fields are zero), and society runs only with `--social`. A parity run says nothing about code that acts only on them; say so in the ledger entry, or add the one run that exercises the change (`--social`; 256 columns with the default duration for mountains; 512 columns for lakes, which the user has postponed). A module that routes water or draws from the shared random sequence turns a rounding-sized change into a different world: compare totals and counts, not cells.
- After a rewrite by pattern, search for what it must never produce and read every rewritten comparison (`git grep -E "belowsea\([^)]*\) *[-+*/]"` must find nothing); compile the changed files with conversion warnings to find numbers still squeezed into integers. Write multi-line edits as script files, never as shell heredocs.
- New modules get an evaluation profile in `configs/evaluation/<module>.json`, not their own benchmark scripts. The world grid is the cube (N = W / 4 cells per face edge); exports, Earth references and lat-lon worlds are cell-centred `W x W/2`. Record seed, parameters, code version, grid and inputs with every comparison; never overwrite prior run evidence. `runs/registry/<module>.json` supplies run IDs; use numeric IDs in new reports. The fixed global-balanced-v1 score gives the numerical recommendation; the user's visual verdict overrides it. Runs and references use the same palettes, `configs/climate-palettes.json` and `configs/tectonics-palettes.json`.
