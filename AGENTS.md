# Undiscovered Worlds

Procedural planetary simulation (terrain, tectonics, climate, hydrology, early society) in C++17/CMake/vcpkg on Windows. `README.md` describes the intended lifecycle; distinguish intended from implemented behaviour. Design and status live in `docs/architecture/` (`world-model.md`: components, process kinds, recipes; `consolidation-plan.md`: target structure, phases and open decisions). `meta/`, `refs/` and `runs/` (except `runs/registry/` and `runs/ledger/`) are local-only and gitignored.

## Working conventions

- Before ending a phase or printing the prompt for the next one, write what the session learned where the next agent will read it (this file, the plan, the ledger, the guides, memory): nothing stays only in the conversation.
- Work directly on `main`; uncommitted changes in the working tree are current work, so build on them and never reset, stash or revert them.
- Every step records its wall-clock duration (user, 2026-10-06), measured from the previous step's commit to the step's own commit (`git log --format='%h %ci'`; the first step of a phase counts from the phase's parent commit). A step's ledger entry has a `duration` field with its start time and the measured duration of the previous step (its own is only known at its commit); the plan's step table has a Duration column, filled with the measured value when the next step marks it. Durations are what the plan's estimates are checked against later.
- A compile build is the default check. Run tests, benchmarks, profile experiments, `check_tectonics_cli.py` or the Python suite only when asked or when a bug persists after a fix; say which checks were skipped. Commands are in `docs/reference-guides/verification.md`.
- The desktop application is compiled, never checked: the user works on the command line for now (2026-10-05), so a change in `src/app` is compile-only and says so in its ledger entry. Seed 1 for every new run; another seed only when the user asks for a seed comparison (20260906 only to reproduce climate runs up to 365). Module checks go through `scripts/uw.py <module> <command>` and the headless CLIs; never launch `UndiscoveredWorlds.exe` for a check.
- Tectonics has exactly one implementation, `src/simulations/geology/plate_tectonics` (namespace `tectonics::`, baseline from `configs/tectonics-baseline.json`). Do not reference or describe any other or former tectonics code. `scripts/check_layout.py` enforces its public-header boundary.
- Delegate read-only surveys to subagents and keep working. Before claiming a run improved anything, have a fresh-context reviewer check the evaluation (paused since 2026-10-05: the user says when reviews start again; `docs/architecture/consolidation-plan.md`, rules of Phase 4). Never write per-run HTML or scripts: reports are rendered from JSON by `scripts/evaluation/`.

## Where things go

- Behaviour in `src/simulations/<module>/`, stage order and recipes in `src/pipeline/`, I/O in `src/io/`, observed-data comparisons in `src/validation/`, GUI only in `src/app/` (its state and screens are `Application`, `src/app/application.hpp` and `src/app/screens/`; the regional map is `src/app/regional/` and no headless target links it). One translation unit per process, named by its process id. `src/world/functions.hpp` is a compatibility umbrella; include the owning header instead. Project headers are included by their path from `src/` (`#include "pipeline/world_processes.hpp"`); each directory is one static library `uw_<dir>` with its own `CMakeLists.txt`. `scripts/check_layout.py` enforces the include root and the layering: `core` includes only `core`; `simulations` and `pipeline` never include `app` or `cli`; SFML and ImGui only in `app`.
- Continuous world quantities are float: elevation and the six components added to it, lake surfaces, temperature, rain. Code in `src/simulations` and `src/pipeline` reads the `...float` getters (`nomfloat`, `mapfloat`, `mountainheightfloat`, `lakesurfacefloat`, `jantempfloat`, ...) and asks `basebelowsea(x, y)` or `surfacebelowsea(x, y)` instead of comparing an elevation with sea level. The getters without the suffix round to whole numbers and exist only for the regional map, the GUI and the `.uww` layout until Phase 5 of the plan ends; do not add callers. The climate rules (`climate_fields.cpp`, `climate_classification.cpp`, `climate_elevation.hpp`) still read the rounding getters of `climateworld`: a float step of its own (plan §11, "Later"). Codes, counts, masks, directions and 0 to 100 scores stay integers.
- Tunable values live in `configs/parameters/<module>.json` (keys in snake_case, read in code as `tuning::<module>::<group>::<camelCase>`). `scripts/parameters.py` generates the tracked `<module>_parameters.hpp` from it (`--check` in the step check); never edit a generated header or add a tuned constant to a source. A run sets a value with `--set <module>.<group>.<key>=value` or `--parameters FILE`, and the bundle manifest records all of them.
- Downloads and receipts in `refs/source/`, prepared inputs in `refs/processed/`, run artefacts in `runs/`, builds and scratch in `out/`. Bulk directories are junctions into `D:/dev/undiscovered-worlds/` (`runs/storage.json`): keep repo-relative paths, never replace a junction with a directory, and create run and report directories through `scripts/uwtools/storage.py` (`run_directory`, `route`). Registered runs live in `runs/<module>/<id>/` (`scripts/uwtools/runs.py` finds a run in either layout); `runs/archive/` is the sealed earlier layout and is never written. `scripts/repository_scope.py` enforces the 5 MiB blob limit and local-only paths.

## Simulation evidence

- Separate deterministic correctness from physical validity: an unchanged seed or a passing test does not show improved skill; compare the affected fields and metrics, and expect a visual review. Observed Earth data are validation inputs, never hidden forcing for procedural worlds; keep assumptions and calibrations explicit.
- A refactor that must not change results is checked with seed-1 `world_pipeline --bundle` runs compared by `scripts/evaluation/compare_bundles.py`, at the minimal configuration (128 x 64, `--duration 50`, `--climate-resolution 32 --climate-coupling-iterations 2`: under a minute for the three recipes); `scripts/evaluation/step_check.py <label> --reference <previous>` does the builds, the three runs, the comparison and the layout, parameter and access checks; larger runs are for judging a module, not for parity; a stage whose writes change keeps its declared access current (`--audit-access`, `scripts/evaluation/process_access.py`). Measure access (the tracking build and its report runs) only when a change alters which fields a process reads or writes, never as a routine check; a change of number type is not such a change. Build the desktop preset only when `src/app` changes.
- What the minimal world cannot show: it has no mountains, craters, ocean ridges or lakes (those fields are zero), and society runs only with `--social`. A parity run says nothing about code that acts only on them; say so in the ledger entry, or add the one run that exercises the change (`--social`; 256 columns with the default duration for mountains; 512 columns for lakes, which the user has postponed). A module that routes water or draws from the shared random sequence turns a rounding-sized change into a different world: compare totals and counts, not cells.
- After a rewrite by pattern, search for what it must never produce and read every rewritten comparison (`git grep -E "belowsea\([^)]*\) *[-+*/]"` must find nothing); compile the changed files with conversion warnings to find numbers still squeezed into integers. Write multi-line edits as script files, never as shell heredocs.
- New modules get an evaluation profile in `configs/evaluation/<module>.json`, not their own benchmark scripts. Grids are cell-centred `W x W/2`. Record seed, parameters, code version, grid and inputs with every comparison; never overwrite prior run evidence. `runs/registry/<module>.json` supplies run IDs; use numeric IDs in new reports. The fixed global-balanced-v1 score gives the numerical recommendation; the user's visual verdict overrides it. Runs and references use the same palettes, `configs/climate-palettes.json` and `configs/tectonics-palettes.json`.
